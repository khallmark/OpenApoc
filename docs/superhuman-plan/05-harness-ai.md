## 3. Architecture: layers, clocks, standing orders, genes

### 3.1 Design principles

- **P1** Decide in a pure module, act in the executor: the planner imports nothing from `oa_play`, opens no sockets, takes plain data in and returns plain data out (the contract `oa_ai.py` keeps for tactics, oa_ai.py:1-20) (replaces F2).
- **P2** Game ticks drive cadence and deadlines; wall time is a watchdog only (F1).
- **P3** Layers arbitrate shared resources by claiming them in priority order; a lower layer spends only what a higher layer left (F5).
- **P4** The observation holds only what a human sees on a named screen; every field carries its surface (section 5).
- **P5** Every order has a post-condition read back from `gs`; failures back off in game time (F7, D18).
- **P6** Memory is serialisable and rebuildable from game state (F4).
- **P7** The control arm is always selectable: `plan=legacy` reproduces today's order of actions.
- **P8** One heavy UI order per pass; multi-click city sequences run paused (168 "not on CityView" refusals, failure_forensics.md §5).
- **P9** A rule that depends on an engine rule the EXE does not share reads its parameter from the `--shims` list the orchestrator passes at launch (derived from the fidelity vector, 06 §2.1: `bad_debt_floor` G8, `hire_caps` RR-09/RR-10, `lab_caps` F-M12, `market_pacing` F-M1/F-M2, `no_stray_fire` F02, `no_gov_craft_fire` F05, `never_retreat_base` BD14a, `garrison_by_presence` BD04, `alien_building_mode = kill_all` VC-1, `no_early_alien_building_research` VC-2, plus `takeover_any_nonzero` for T1+T2 absent). One rule text then serves the faithful and the unfixed binary, a shim switches itself off when its fix lands, and the policy never reads the manifest, provenance or `gs fidelity`.

### 3.4 The planner contract and the executor loop

```python
@dataclass(frozen=True)
class Order:
    rule: str; verb: str; args: dict      # "GOV-SWEEP", "raid_building", ...
    layer: int                            # 0 SURVIVAL .. 3 OPTIMISATION
    deadline_tick: int|None               # game-time deadline; None = best effort
    claims: tuple                         # ("soldiers", base, n) ("cash", $) ("craft", id) ("ui", "heavy"|"light")
    why: dict                             # the observable values that fired the rule (goes into the trace)

class StandingOrder:
    rule: str; layer: int; cadence_h: float
    def when(self, obs, mem, clock) -> bool: ...
    def orders(self, obs, mem, clock) -> list[Order]: ...
    def until(self, obs, mem, clock) -> bool: ...    # release; default: not when()
```

`CampaignAI.decide(obs, mem)`: (1) evaluate each standing order of the active plan whose `cadence_h` has elapsed in game time; (2) collect its orders; (3) claim pass in layer order against a `ResourceBook` seeded from the observation (soldiers per base = healthy, loaded-armed, present; cash = balance minus the SV-07 reserve; craft by id; UI budget); an order whose claims fail moves to `mem.deferred` with the reason; (4) return survivors sorted by (layer, deadline, plan position). The claim pass makes the ordering bugs of 4.4 structurally impossible.

```
run_turn():   t = clock.read(); skip if not due and no interrupt
              obs = observe_campaign(caps)            # gs queries only
              mem.absorb(obs, t); orders = ai.decide(obs, mem); speed.govern(orders, t)
              for o in orders: defer a second heavy order; out = verify(execute(o)); mem.record(o, out, t)
                               stop the pass if the stage changed; trace.append(...)   # decisions.jsonl
```

`on_alert_screen(st)` calls the same ALERT-TRIAGE order with an observation restricted to what the AlertScreen displays (owner, function, `threatens_base`), so the alert path and the raid path share one odds policy (F3).

### 3.5 Clocks and the SPEED rule

- `GameClock` reads `gs time` (gamestateintrospect.cpp:267-272). Weekday and hour-of-day are parsed from the displayed date and time as a player reads the HUD; the epoch is never hard-coded. One game-hour is 518,400 ticks, one day 12,441,600 (gametime.h:9-14). The first Monday midnight is about 5.5 game days after the Tuesday-noon start [EXE G1, RF §3.1].
- Wall time is used only for stage-wait timeouts, UI retries, the run watchdog and the poll sleep.
- One `observe_campaign` per `OBS_PERIOD` game-hours (gene; initial 4 h, fitted from `hours_alert_to_contact`) and after any stage change or alert.
- SLA to speed. A SURVIVAL order carries a deadline in game-hours. With H(s) the calibrated game-hours per wall-second and P the poll period, the governor allows the highest speed with `H(s) x P <= SLA / 2` [DERIVED from oa_victory.py:838-841]. At Speed 5, H x 0.8 s = 4.2 game-hours per poll, so any SLA under 8.4 game-hours forbids Speed 5 unless the poll shrinks to `SLA / (2 H)` (about 0.19 s for a 2-hour SLA); `govern()` shortens the sleep first, drops a speed level second. M1 `calibrate_speeds()` measures H(s) on the benchmark machine.
- Pause-to-act. Key `0` is Pause (cityview.cpp:4332-4333). `caps.paused()` presses `0`, runs the sequence, restores the previous level in `finally`; used for select-craft-then-order, crash-site recovery orders, base purchase placement. Opening a sub-screen already stops the clock (oa_victory.py:846-849), so BaseScreen / ResearchScreen / BuyAndSell passes need no pause.

Speed table (SV-09), first matching row wins:

| Observable condition | Max speed |
|---|---|
| a queued alert with `threatens_base`, or a queued Government-owned building, or a sweep deadline within 2 x (game-hours per poll), AND a dispatch is claimable inside the SLA (a squad of at least `squad_floor` exists above the SV-04 claim, or is already flying) | highest speed meeting the SLA equation |
| the same triggers but NO claimable dispatch | fall through: slowing the clock cannot create a squad, and holding a low speed without being able to act is the "permanently at speed 3" trap the harness removed once (oa_victory.py:863-878) |
| sweeps pending, an eligible squad exists (`armed >= infil_min_armed`) | `infil_speed` gene, in BOTH branches |
| a hostile UFO is in the city, or a squad is en route or in a building | 3 under the new plans (03 TIME-1: the hover and hourly samples must be seen); 4 under `plan=legacy` |
| nothing pending | 5 if `turbo.can_turbo == 1` else 4 (03 TIME-1: 5 only when none of the above holds) |

## 5. Observability

### 5.1 The rule

The campaign AI may read **live state a human can read on a named screen** and **static rule knowledge a human can learn from the UFOpaedia or a published guide**. It may not read hidden live state: exact alien crew counts, raw infiltration values, the aliens' knowledge of our bases, engine bookkeeping such as `lastStock`, global foe counts in a battle. Every query below names the screen and control that shows its fields and has an allowed-key test. The per-organisation ALIEN INFILTRATION graph (current percent plus daily history) is a legitimate surface and the Government-containment loop's main input.

Open as OQ4: priors from shipped static data (function infiltration speeds, UFO crew sizes, the SV-04 attacker table) are used only where a guide or the UFOpaedia publishes the same table, with the source beside each constant. Quantities no screen shows and no guide publishes (max market stock, the base exposure word, raw infiltration, the pending incident list) are never read; 5.3 names the replacements.

## 6. Roadmap: milestones M0-M10 with Gate A

### 6.1 Working rules for every milestone

1. **Test at the seams that exist today** ("a row is not done until the lock test fails without the change", docs/HANDOFF.md:23, 116): each behavioural test targets a seam present on the pre-change tree (`Victory.city_turn` through the `turn()` helper of test_oa_learn.py:194-296, `Victory._run`'s alert branch, `recover_crash_sites`, `build_final`, `oa_learn.reward`) and fails there with an `AssertionError`, never an import error; unit tests of new pure modules do not count as fail-before evidence; a guard that today's code already satisfies is a mutation guard and must fail when the guarded check is deleted.
2. **ORDER, not presence.** Attach every patched helper to one recorder (`rec.attach_mock`) and assert on call indices; speed tests assert the full `set_speed` argument list.
3. **Red, green, red.** Keep the failing output, implement, run green, set the change aside as a WIP commit (never bare `git stash`) and confirm red again.
4. **Control arm.** Every behaviour change is selectable by `plan=` or a gene; the protocol is 06's: same engine build hash and fidelity vector (M0), budgets in game days by tier (T1 scenario saves, T2 to day 21, T3 to day 42), Monday checkpoints at days 7, 14, 21, 28 (M1), a `plan=legacy` A/A first to measure run-to-run spread, then the treatment arm. A 16-window batch suffices for the A/A and operational scenarios; a survival verdict needs 06's larger samples. A claim is accepted only if the treatment moves by more than the legacy-vs-legacy spread and the control did not move; a one-armed result is never accepted.
5. **CI.** New tests are `tools/test_oa_*.py` (job `python3 -m pytest -q tools/test_oa_*.py`, `.github/workflows/harness.yml`).
6. **Patch reachability.** Seam tests that patch helpers assert through the M2 guard fixture that no real `oa_play` helper ran.
7. **Landing.** Use an agreed committed descendant and check current ownership before edits to `oa_victory.py`, `oa_play.py` and shared C++ files (section 7). The old LIVE work has already landed locally.
