Verdict

OpenApoc already extracts and consumes ~30 live rule-table groups from the ISO non-4 EXEs (research, vehicles, economy, orgs, TACP equipment). The remaining original-game work is not “find more blobs.” It is logic the tables do not encode, plus a handful of hexa ranges still patched or hardcoded: 36 TPS per mechanic, mission defaults, cover AI, manufacturing, UFO growth, and hazard constants.

Steam depot is the wrong extract target. Depot UFO2P.EXE / TACP.EXE are the Pentium 4 builds (CRC 0xdbd3b41d / 0x3ec9c268). Extractors accept exactly one CRC each (0x4749ffc1 / 0xfebbe39e), LogError, and continue with non-4 offsets — garbage tables. They do not abort.
144 TPS is intentional, not a typo. VANILLA_TICKS_PER_SECOND = 36 × TICKS_MULTIPLIER = 4. Issue 997 is a per-mechanic audit: which rates already scale by 4, and which still run four times too fast. City Speed1 is also flagged as possibly half of original Speed1.
32 hexa ranges have no extractor header — bytes are already dumped. Highest-value city misses: UFO_mission_data, manufacturing_data, UFO_growth_rates, vehicle_park_spawn_table, senate_relationships. OpenApoc stands in with patch XML and hardcoded maps.
Pass 1 claims that did not survive source check. Org vehicle-park refill does check funds (organisation.cpp:753). Tactical retreat chance is no longer integer-zero. Agent Teleport is a handled case that returns false, not the default branch. Flattened function exports are polluted — treat census as coverage, not a named map.

Binary identity

CRC32 is zlib/ISO-HDLC, the family OpenApoc extractors use. Depot XCOMA/ city and tactical EXEs are byte-identical to the ISO Pentium 4 pair, not the ISO non-4 pair. Win95/autorun helpers are inventoried and will not be analyzed.

Extractor pipeline versus runtime

Extractors build a GameState, then GameState::saveGame() writes XML under mods/base/. The game loads that state at boot. Several EXE blobs are loaded and then ignored; several live systems are patch XML or hardcoded maps instead of tables.

What to build next

From the matrix. Ghidra and decompiler output are allowed on this fork.

  1. Ticks per second (issue 997) — 144 TPS is 36 × 4 on purpose. Audit one mechanic at a time: which rates already scale, which still run 4× too fast, and whether city Speed1 is half of original Speed1.
  2. Agent city mission defaults (agentmission.cpp) — Investigate Building is string-backed. Teleport is a handled getNextDestination that returns false; remaining types still hit default. Blocks alpha agent flow (issue 263).
  3. Vehicle mission stubs (vehiclemission.cpp) — same shape as agent missions; needed before ground lanes. Road-layer strings exist; lane-keep rules do not (issue 785).
  4. Organisation vehicle buy/sell (issue 1053) — park refill and a funds check exist; purchase() still never credits the seller.
  5. Battle cover / potshot modes (issue 265) — specified in ai.txt; TACP strings name Cautious / Aggressive / kneel. Use ai.txt plus TACP decompiler.
  6. Enzyme / fire / cloak constants — names are string-backed (Entropy Enzyme, Personal Cloaking Field). Replace “made up” values in battlehazard.cpp after original observation.
  7. Victory / defeat / takeover screens — city strings X-COM IS DEFEATED, THE ALIENS ARE DEFEATED, ALIEN TAKEOVER; launcher already names smk/lose1.smk and smk/wingame2.smk. OpenApoc already plays SMK.
Extractor follow-on (not gameplay): teach ufo2p.cpp / tacp.cpp the 4-build CRCs and the per-table deltas, or keep extracting from the ISO non-4 pair only.

Method and limits

  • ISO non-4 is extractor-canonical. Depot un-suffixed EXEs are the 4 pair.
  • Table offsets are bound-file offsets. Do not unbind with DOS32A.
  • Function export used a reconstructed LE image + BinaryLoader. String literals did not survive into those decompiles; string evidence comes from the EXE catalogs.
  • Raw function export is polluted by non-executable objects. Treat it as coverage, not a named map. callingConv is still unknown.
  • Negative string search does not prove a behavior is absent (cover, potshot, umbilical, mushroom).
  • Listings live in the sibling lab and depot_7661/analysis/. Cite binary + generation + file offset when pasting names here.
