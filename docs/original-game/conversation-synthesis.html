Executive summary

The conversations formed one overlapping research and implementation campaign, not eight independent studies. Together they established a usable macOS build, a reproducible Ghidra lab, a broad CTest harness, and a large evidence-gated parity patch.

Current truth: the older headline “39 implemented / 10 missing” is stale. The current gap matrix records 43 implemented systems and 9 missing systems. A separate nine-item queue tracks partial or unbound behavior inside otherwise implemented rows. “Implemented” therefore does not mean every byte or original consumer is understood.

What was established

  • ISO non-4 UFO2P/TACP binaries are extractor-canonical.
  • Pentium 4 binaries need per-table rebasing, not a universal slide.
  • Original behavior can be tied to tables, xrefs, listings, tests, and file offsets.
  • The fork now has a repeatable parity workflow and evidence hierarchy.

What was delivered

  • Research, manufacturing, economy, UFOPaedia, organisation, mission, and battle fixes.
  • New extractor tables and CRC-aware support for both EXE generations.
  • A custom 26-test CTest suite with shared deterministic helpers.
  • Gap matrix, subsystem notes, extractor index, and generated compare report.

What remains uncertain

  • Cover/potshot AI, several battle timing constants, and multi-tile rules.
  • Mission-pattern runtime consumption and subversion arrival behavior.
  • Vehicle attack-mode dodge, city action music, and diplomacy formulas.
  • The complete UFO mission-tail and +0x168 vehicle gate model.

Status separates recovered evidence from implementation. A partial finding can be well evidenced while still lacking enough state or consumers for a safe port.

Binary identity and rebasing

ISO non-4 UFO2P CRC 0x4749ffc1 and TACP CRC 0xfebbe39e are extractor-canonical. Depot unsuffixed EXEs are the Pentium 4 pair (0xdbd3b41d and 0x3ec9c268). TACP commonly slides -0x2200; UFO2P is often +0xE00, with exceptions such as crew_ufo_downed. The implementation therefore uses per-table mapping.

Vehicle threshold and spawn gate

FUN_000588f8 gate instruction at file 0x48924; FUN_0004dd14 entry at file 0x3DD13, ratchet instruction at 0x3DFF1

Vehicle +0x168 starts as constitution × type-percent / 100. FUN_000588f8 checks it against +0x12e, requires the low word of +0x12c to be zero and the city dimension to be active, then enters FUN_00051348. FUN_0004dd14 ratchets the threshold during building-mission routing. The low-word meaning, live +0x12e writers, and +0x16a flag are still unknown, so the full gate must not be wired.

TACP fire chain

FUN_0007c110 file 0xD6BB4; power table 0x2E2AF4

Equipment unknown01 is fire/hazard item resistance. The item damage formula uses factor=(power+19)/20 and subtracts the resistance percentage. The tile overlay index is its low six bits and FUN_0007b3dc increments the overlay byte. OpenApoc’s hazard age/power are not proven equivalents; placement RNG, cadence, spread, and stage-to-power mapping remain unbound.

Method and source scope

Corpus

Eight completed conversation records plus 264 additional supporting worker transcripts after deduplicating the two worker runs that were also promoted into their own conversation records. The current report-generation conversation is excluded. Worker runs are supporting evidence, not independent confirmation.

Authority rule

When transcripts conflict, current openapoc-gap-matrix.md, next-implementation.md, and extractor-tables.md win. A decompiler claim is not treated as final when later listing or raw-byte evidence corrects it.

Evidence hierarchy

Table → string → xref → decompiler/listing → prior art → OpenApoc TODO. Original-behavior claims should identify binary generation and file offset. Missing strings or xrefs are reported as “not recovered,” not proof that behavior never existed.

Validation boundary

The report records test results stated in the source conversations and compares them with the current test registration count. It does not claim that this report-generation pass reran the full game suite.
